# Advanced WebSocket Pro (Fixed Version)

> A more stable and robust WebSocket extension, specifically designed for CCW / Gandi online games and real-time communication scenarios.

[中文](README.zh.md) | [English](README.md)

## 🎯 Design Goals (What Problems It Solves)
The original `advancedWebSocket` and the basic modified version `MiaosAdvancedWebSocket` have some pain points in use. This Pro version aims to completely fix them:
1. **Reconnection loses URL**: The original version would fall back to the default `localhost` when reconnecting, which has now been fixed.
2. **Infinite reconnection in background**: Fixed the bug where after manual disconnection, it would still secretly "do sit-ups" and reconnect crazily.
3. **Memory leak risk**: Added `PROJECT_STOP_ALL` event listener to automatically clean up resources when the project stops.
4. **Message type matching and output**: Fixed type mismatch and optimized the `[object Object]` output format.
5. **CCW sandbox adaptation**: Added CCW standard Base64 inline SVG icons, eliminating external resource requests and perfectly adapting to the sandbox.

## 🎮 Core Features
- **Connect/Disconnect**: Supports any WebSocket server address.
- **Multi-type sending**: Send text messages, JSON messages, commands.
- **Event receiving**: Supports event blocks such as "when text message received", "when command received", "when connected", "when disconnected".
- **Reconnection policy**: Customize max reconnection attempts and interval.
- **Status reporting**: Provides reporter blocks like "connected?", "last received message", "message type", "command parameter".

## 📨 Server-side Received Content Description (JSON Message Structure)

All internal communication of the extension is based on **JSON strings**. When sending, they are automatically wrapped by blocks; when receiving, it tries to parse as JSON; if parsing fails, it automatically treats as plain text.

### 1. Send Text Message (`Send Text Message` block)
```json
{
  "type": "message",
  "data": "Hello Scratch!",
  "timestamp": 1758720000000
}
```
- `type`: Message type, customizable in the block (default `message`).
- `data`: String content.
- `timestamp`: Millisecond timestamp, automatically generated by the extension.

### 2. Send JSON Message (`Send JSON Message` block)
```json
{
  "type": "data",
  "data": { "key": "value" },
  "timestamp": 1758720000000
}
```
- The `data` field can be any JSON object or array.
- Note: If invalid JSON is entered in the block, the extension will report an error and ignore this send.

### 3. Send Command (`Send Command` block)
```json
{
  "type": "command",
  "command": "move",
  "params": "forward",
  "timestamp": 1758720000000
}
```
- `type` is fixed to `"command"`.
- `command`: Command name, customizable in the block (default `move`).
- `params`: Parameters attached to the command, string type.

### 4. Receive Normal Text / JSON Message
When a valid JSON is received and `type` is not `"command"`, the `When [TYPE] text message received` block is triggered.

**Example received data:**
```json
{
  "type": "move",
  "data": { "x": 5, "y": 7, "player": "A" },
  "timestamp": 1758720000000
}
```
**Block outputs:**
- `Last received message` → `{"x":5,"y":7,"player":"A"}` (if `data` is an object, automatically converted to string)
- `Last received message type` → `move`

### 5. Receive Command
When a valid JSON is received and `type` is `"command"`, the `When command [COMMAND] received` block is triggered.

**Example received data:**
```json
{
  "type": "command",
  "command": "placePiece",
  "params": "5,7",
  "timestamp": 1758720000000
}
```
**Block outputs:**
- `Command parameter` → `5,7`
- `Last received message type` → `command`

### 6. Plain Text Fallback
If the received data is not valid JSON, the extension automatically wraps it as:
```json
{
  "type": "text",
  "data": "This is a plain text"
}
```
and triggers the `When [text] text message received` block.
At this time, `Last received message` returns the original string.

### 7. Connect and Disconnect Events
These two events **do not carry JSON data** and are only triggered internally by the extension:
- `When connected`
- `When disconnected`

### 8. Reconnection Policy Settings
The `Set reconnection policy` block only affects internal behavior and does not generate network messages.

> **Recommendation**: When customizing message types, try to use meaningful English words (such as `boardSync`, `chat`, `heartbeat`) for easy identification in the block dropdown menu.
